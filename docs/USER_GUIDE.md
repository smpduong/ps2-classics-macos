# PS2 Classics for Mac — quick start

Open **dist/PS2 Classics for Mac.app**. This is a native release candidate for macOS 12 and later, with Intel and Apple Silicon code in the same app. No Python, Wine or Homebrew is needed to use it.

## First package

1. In **Setup**, import your existing support folder or choose its files individually: a 16-byte binary klicensee, matching 16-byte RAP, PS3LOGO.DAT and a blank formatted SCEVMC0.VMC. Enter the corresponding content ID. The app does not supply production support assets or validate your console's license installation. Setup warns early if a selected key is really a RAP/RIF, if a key or RAP is the wrong size, if the content ID disagrees with the RAP filename, or if files were picked individually rather than as one imported set. You can save the current set as a named **support profile** and re-apply it later; applying one checks that each file is present, readable, a regular file (never a directory or symlink) and the expected size, but it does not prove the assets match your console. A profile records the real folder a set was imported from, or nothing when files were picked individually.
2. In **Build a package**, add your image. ISO, raw MODE1/2352 and MODE2/2352 BIN, and single-data-track CUE starting at 00:00:00 are supported. CHD v5 DVD and single MODE1, MODE1_RAW or MODE2_RAW CD tracks are supported, including parent-dependent (delta) CHDs once you choose their exact parent file. A parent-dependent disc shows which parent identity it declares; use **Choose parent…** beside the disc and the app verifies the pair immediately. Both the image and its parent stay unchanged, and the parent's exact bytes join the build fingerprint, so swapping the parent later rebuilds rather than reuses. Only single-level parents are supported; deeper chains must be flattened first. Multi-track/audio CHDs, older CHD versions, pregaps and subchannel data are rejected with the exact reason. Audio/mixed-track CUE and pregaps are not supported; the app names the exact unsupported case (audio track, other sector mode, multiple tracks, INDEX 00 pregap, non-zero start, non-BINARY FILE or a multi-file layout) instead of a generic error.
3. Review the game ID extracted from SYSTEM.CNF. If it cannot be found, enter the correct ID manually. A detected conflicting ID blocks building until corrected. File size is never used to decide CD versus DVD.
4. Set a display title and installation title ID. Select a CONFIG if the game needs one; the app records its SHA-256 and your source/version note. Use **Find matches…** to search your local CONFIG library by exact game ID and choose among matching variants. Manage the library folder in **Setup**, which shows whether the folder is available and offers **Refresh**, **Reveal** and **Clear**. If a saved library is missing, disconnected or unreadable, the app says so plainly and lets you reconnect or re-choose it without affecting your projects. Each candidate shows its relative filename, fingerprint, size and modification date for provenance; a match does not establish compatibility. A selected CONFIG is required data: if its file is missing, unreadable, empty or oversized when the build runs, the build fails before any conversion rather than silently building without it. To build without a CONFIG, clear the selection explicitly.
5. Optionally choose icon/background images and fit or crop. **Find artwork…** can scan a local folder for PNG/JPEG images whose name begins with the disc's exact game ID, showing bounded previews and dimensions; nothing is applied until you choose **Use as icon** or **Use as background**. Choosing **Change folder…** re-scans and immediately replaces the shown matches, and closing the sheet cancels a scan in progress so it cannot reopen or repopulate later. Without artwork, the app generates a title card. For sound, **Choose AT3 sound…** imports an existing SND0.AT3 file, and **Convert audio to AT3…** converts mono/stereo PCM WAV, AIFF, MP3, AAC/ALAC M4A, or FLAC into an ATRAC3 (AT3) file with the bundled native encoder. macOS automatically resamples supported 8–192 kHz audio to 44.1 kHz, 16-bit PCM. Mono is duplicated to both output channels; stereo stays stereo. Clips must be at most 2 minutes 30 seconds and 512 MB; surround audio and protected/unsupported codecs are rejected. Conversion can be cancelled and never overwrites an existing file. No FFmpeg or other installation is required.
6. Choose a new .pkg destination and select **Build package** (⌘↩). Allow roughly twice the expanded input size plus a safety margin free at that destination. The app checks the destination's filesystem, per-file size limits, path length, free space and writability before starting. CHDs also need expansion space. Temporary files live there and are removed on success, failure or normal cancellation.
7. A completed job links to the package and a separate JSON report. **Locally verified** means the implemented payload and round-trip checks passed. It does not mean PS3-tested.

The package format is a debug package for compatible modified-console workflows. EDAT signature fields are placeholders from that reference workflow, not Sony signatures. On the console, installation, launch, saving and game compatibility must still be validated with your real support files.

## Multiple discs

Add all discs for one game to one project, reorder them with the arrows, and review each disc's ID. Xenosaga II's two supplied images have different IDs; retain those per-disc IDs. The first disc's ID is the suggested installation ID. Multi-disc builds include DISC.IDX, individually numbered encrypted images and per-disc CONFIG title trailers. Disc switching is experimental until tested for that title on the console.

## Saved projects and queue

Use **Save project** to store a .ps2project file. This stores settings and file locations, not copies of games or key bytes. Keep the referenced files available. After changing a CONFIG externally, select it again to explicitly accept its new fingerprint.

**Add to queue** saves a snapshot. Editing the current project does not alter that snapshot. **Start queue** processes jobs serially (⌘R). Only one operation runs at a time: importing discs, image tools, memory-card conversion, cache clearing and package checks wait while a build runs, and a queued build waits while any of them run. Adding discs inspects the image in the shared slot and can be cancelled while it works. Pause after the current job, or cancel the current build (⌘.). Failed/cancelled jobs can be retried. A retry restarts the job but reuses already-verified encrypted disc images only when every input is unchanged: the exact source, CONFIG, key/RAP/logo/card, content ID, title, artwork and helper bytes used before. Reused stages are still re-checked against the current source before publication, under the same stability rule as fresh stages. Changing any input means the affected stages are rebuilt. A retry never resumes a partially written encryption stream.

While a job runs, each fully verified encrypted image is checkpointed immediately into a bounded, verified **stage cache** beside the destination, so an interruption loses at most the stage in progress. Build queue shows its size after you choose **Measure** and lets you **Clear stage cache** (moved to Trash); clearing never touches originals or finished packages. The cache is removed automatically once it is older or larger than the built-in limits. Caches from older app versions are never trusted and are left for manual review.

Queue and session state are stored under `~/Library/Application Support/PS2 Classics for Mac/session.json`. Jobs interrupted by an app/OS crash become **Interrupted** on reopening and require review/retry. No queued job starts automatically on launch. If a package already exists at an interrupted job's destination, the app says so and offers **Check published package**: it re-verifies the file read-only and compares the package digest, content ID, title ID and disc images against that job's own completion record. That record is accepted only when it matches a durable build attempt the queue recorded when the build started — the attempt captures the ordered source and CONFIG hashes, the support and artwork hashes and the fit/crop setting actually used, before encryption began. Only a full match becomes "Locally verified (recovered)"; a structurally intact but unconfirmed package, a job queued by an older app version, or a record whose attempt cannot be found stays explicitly unconfirmed. The neighboring report and the attempt record are read with a hard size cap off the main thread; the report is local evidence to compare, not tamper-proof provenance. Cancelling the check leaves everything untouched. It never overwrites the package and never assumes it is valid from its name alone.

Sessions saved by earlier versions are migrated on open: the project, queue order, statuses, destinations and any recoverable identity are kept, and a setting missing from an older queue entry is recovered from that job's own saved project. Whenever the file is not read cleanly, the app first keeps a byte-for-byte copy beside it (named `session.json.unreadable-<date>.json`), tells you the name and offers **Reveal backup** to open it in Finder. If it cannot even make that copy, it leaves the file untouched and will not save over it until you move it aside. A single damaged or unreadable queue entry no longer discards the rest of the queue: valid items keep their order, and a damaged position is preserved as an **Interrupted** placeholder that stays unconfirmed rather than being silently dropped. If a recovered entry repeats another entry's identifier, it is given a new one so removing or retrying one row can never affect another; that reassigned row is kept but its recovery evidence is cleared, so it stays unconfirmed instead of matching the wrong output.

A forced process kill or power loss can leave an isolated `.ps2-build-*` workspace, a `.ps2-image-*` workspace or a `.partial.*` file at the destination. These never replace an original or a finished output. Use **Review interrupted work…** in Build queue to list them: entries the app can prove it created show **Move to Trash** (a reversible action, with the lock held through removal); anything that merely resembles app naming is shown as **Review manually** and cannot be deleted here. Retained stage caches are managed by the cache controls above, not by this review. Cleanup is disabled while a job is running, and it never touches a workspace that a live process is still writing. Normal cancellation cleans these files automatically.

## Image tools and memory cards

**Image tools** starts with the current project's klicensee/content ID and prepares/encrypts images. For decryption it exposes the full ISO.BIN.ENC / ISO.BIN.ENC2…ISO.BIN.ENC9 profile set: choose the profile matching the disc number, or use **Detect profile** (needs no key) to read which logical name sealed the file. **Verify only** re-checks the header, every segment hash and the disc numbering without writing an output file; it shows progress and can be cancelled. Choosing an image, detecting its profile and verifying all run through the same shared operation slot and can be cancelled, which stops the helper that was launched. Only one image operation runs at a time, and changing the source or key is blocked while it runs. Encrypting a parent-dependent CHD asks for its parent the same way package discs do. Decrypted images retain their padding/LIMG; a decrypted payload is not automatically the original ISO. Numbered package-image headers are also handled by the package workflow and command-line helper.

While a disc is selected, the same **Disc number** and **Image profile** controls combine: disc 1 uses ISO.BIN.ENC, disc 2 uses ISO.BIN.ENC2, and so on. A file sealed as a CONFIG record is reported as such and is not treated as an installable image.

**Memory cards** converts between plain VMC and standard CEX VME. Supports 8/16/32/64 MiB cards with ECC, including the additional 16 KiB template form. Always choose a new output; your original is the backup. Conversion is reversed locally and compared byte for byte. This does not repair damaged saves or handle every per-console protected format.

## Troubleshooting

Use **Export diagnostics…** in Setup or Build queue to save the app/system version,
game IDs, selected CONFIG fingerprints, missing setup items and queue errors as JSON.
It contains no game payloads or key bytes and is never uploaded automatically.
Error messages and CONFIG source notes may contain local paths; review the report
before sharing it. New projects retain the current support set. Opening a saved
project restores that project's own settings.

## Before distributing

This build is a **1.0 release candidate**: the local workflow and its automated checks pass, but the external acceptance gates in [CLIENT_ACCEPTANCE_CHECKLIST.md](CLIENT_ACCEPTANCE_CHECKLIST.md) are still open. It is ad hoc signed for local testing, not Developer ID signed or notarized. Cross-compiled Intel code has not been executed on the client's Monterey MacBook Air. Before an external 1.0 release: test that machine, the M4 mini and the target PS3; complete signing/notarization. The approved public license is GPL-3.0-only; distribute the exact matching source archive with binary releases. Third-party license notices are included in the bundle.

## Audio and destination safeguards

Audio exports remain available if you switch projects while encoding. The app only selects the result as the package sound when the original project and its sound selection remain unchanged. Cancelling before publication leaves no finished audio file. Truncated WAV payloads and inconsistent PCM frame layouts are rejected; large metadata chunks are skipped without loading the audio into memory. Decoding/resampling also uses small blocks, and cancellation during this stage removes its private workspace.

Build packages and export audio on an APFS or Mac OS Extended volume, then copy completed files to exFAT if needed. RC4's exFAT placeholder/rename workaround could replace a file created by another process during publication, or leave an empty final filename after a crash. RC5 refuses destinations that cannot provide exclusive publication, before starting expensive work. Physical USB and console acceptance remain outstanding.

## Verified card backups

In **Memory cards**, choose a card and use **Create verified backup**. The new `.ps2cardbackup` folder contains a card copy and a manifest with its size and SHA-256. The app checks the card framing and reverses a conversion to check byte integrity. Keep the entire folder. **Restore backup to new file** verifies the manifest, copied bytes and format before publishing a new VMC/VME. Existing cards/backups are never replaced.

Use **Browse saves…** to list the individual saves on a card: each save folder with its files and byte counts. This is a read-only listing; deleted entries are omitted and damaged filesystems are reported precisely instead of guessed. **Export save…** copies one save into a new `<name>.ps2save` folder with a manifest recording every file's size and SHA-256; each file is re-read from the card and re-hashed before it is written, and the card itself is never modified.

**Import save…** writes a previously exported `.ps2save` folder into a NEW card file: choose the export, then choose a new destination filename with a matching extension (`.VMC` for unencrypted cards, `.VME` for encrypted ones). The app copies the card first and works only on that copy — the original is never opened for writing. Only our own verified exports are accepted (other folders, tampered files, existing save names and full cards are refused with the reason), and the copy is fully verified before publication: per-page ECC of written pages, a full re-parse with the new save byte-exact and every other save unchanged, a check that only intended pages differ, and a helper round trip. If anything fails, no file is published; if verification is cancelled after the new file is written, that file is removed rather than left unverified. Imported cards use freshly generated ECC bytes; whether a console accepts an imported card still needs testing on real hardware, so keep a verified backup of anything important. Writing into an existing card in place is not offered. Cards in the extended 16 KiB form are listed as unsupported for browsing; use whole-card backup for those. Console save acceptance still needs testing on real hardware.

## Manuals

Use **Choose manual** in package details to select an unlocked PDF (1–100 pages) or a single PNG/JPEG image, up to 32 MB (images at most 64 megapixels and 32,768 pixels per side). Pages are fitted onto a 960×768 white background and compressed to the console manual format. The source remains unchanged. The project and queue retain the manual selection, and generated page hashes belong to the durable build attempt. PS3 display/navigation still needs acceptance testing. Remove the selection to build without a manual.

## Online CONFIG catalogs

Open **Online CONFIGs**, enter a direct HTTPS catalog URL, then choose **Load / refresh**. Review the publisher, revision and declared license. Search by the exact game ID and explicitly download an entry into a chosen local library folder. The app enforces the advertised size and SHA-256 before saving the CONFIG and catalog/download receipts in a fresh folder. A successfully reviewed catalog is also kept as an offline copy; typing the same address later offers **Use cached copy** with its retrieval date, so entries stay reviewable and downloadable without a network connection. **Forget** removes that copy. Refresh only replaces the cached copy after another explicit load, and never changes existing project selections. Use **Choose CONFIG** in the package view to select that copy. Downloaded copies remain usable offline; refreshing a catalog never changes existing project selections. Redirects are not followed. No public catalog is bundled or endorsed. The publisher schema is documented in `docs/ONLINE_CONFIG_CATALOG.md` in the corresponding source.

## FTP transfer

Open **Send to PS3**. Start your console’s FTP server and enter its address, port, login and destination folder. The displayed `/dev_hdd0/packages` is an editable starting value, not a detected console setting. The destination folder itself must already exist on the server; the app only creates its own uniquely named folder inside it. Choose an existing completed package, then **Transfer and verify**. FTP is unencrypted, so use a trusted local network. Login details are not saved and the password is cleared after the attempt.

The app verifies the local package, creates a fresh `PS2-…` directory remotely, uploads `package.part`, streams the entire file back for a size/hash comparison, confirms the local file is unchanged, then renames to `package.pkg`. This uses about two package sizes of network traffic. It never overwrites an existing console directory. Locate the reported folder with the console file manager to install the package; the console’s installer may not scan nested folders automatically. An interrupted transfer leaves its uniquely named folder for inspection and is not automatically resumed or deleted. A disconnect during final rename can leave either name; inspect the reported folder before retrying. Transfer verification does not establish installation or game compatibility.
